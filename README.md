# CSDVideoSegment

End-to-end case-based endoscopy phase segmentation.  This repository uses the
MedGemma 1.5 4B **Stage 1 four-phase checkpoint** from the ESD phase
experiment (`Diagnosis`, `Local injection`, `Incision / Dissection`, and
`Hemostasis`).

## PhasePro MAX GUI

The repository also includes a web-based timeline editor for reviewing and
correcting generated phase segments.  It supports multi-video cases, project
history, elastic timestamp editing, and CSV export.

For the complete frontend setup and usage guide, see
[Frontend & Web Editor Guide](./frontend/README.md).

Quick start:

```bash
# from the repository root
python server.py

# in another terminal
cd frontend
npm install
npm run dev
```

Then open `http://localhost:3000`.  The backend must be running first because
the GUI reads video files and model-generated CSVs through the API.

## What changed

The video runner is now a producer/consumer pipeline:

```text
videos --parallel ffmpeg--> completed-case queue --GPU--> filters -> MedGemma -> phase CSV
```

Frame extraction for later cases continues while the GPU analyses the current
case.  MedGemma is loaded once per run instead of once per case.  Existing
clarity filtering, three-model need voting, and the final CSV schema are kept.

## Model path

The canonical local phase checkpoint recorded in
`../esd_phase_docs/run_manifest.tsv` is:

```text
/mnt/t24c/mumulin/LlamaFactory/saves/campaign_nested/medgemma-1.5-4b/fold0
```

The path is a runtime mount/reference only.  No checkpoint is copied into this
repository or Docker image.  Override it when running another phase fold:

```bash
export CSD_MEDGEMMA_MODEL=/mnt/t24c/mumulin/LlamaFactory/saves/campaign_nested/medgemma-1.5-4b/fold0
```

The public `google/medgemma-1.5-4b-it` model can be used for a smoke test, but
it is not a replacement for this Stage 1 phase-finetuned classifier.

## Environment

### Docker (recommended)

Build once on the machine where the workload will run:

```bash
docker build -t csd-videosegment:medgemma15 .
```

Run without copying videos, frames, or checkpoints into the image.  Mount the
repository data and the checkpoint's network-zone path read-only:

```bash
docker run --rm --gpus all \
  -e CSD_MEDGEMMA_MODEL=/models/medgemma15/fold0 \
  -v "$PWD/data:/opt/CSDVideoSegment/data" \
  -v "$PWD/results:/opt/CSDVideoSegment/results" \
  -v "$PWD/.work:/opt/CSDVideoSegment/.work" \
  -v /mnt/1248/open2/mumulin/endoscopy_dataset/raw_data:/mnt/1248/open2/mumulin/endoscopy_dataset/raw_data:ro \
  -v /mnt/t24c/mumulin/LlamaFactory/saves/campaign_nested/medgemma-1.5-4b:/models/medgemma15:ro \
  csd-videosegment:medgemma15 \
  --cases-file /opt/CSDVideoSegment/configs/cases.txt
```

The checkpoint mount must be available on the host.  Do not move it between
the `/mnt/t24c` zone and the `/mnt/1248` zone.

### Conda

```bash
conda env create -f environment.yml
conda activate CSDVideoSegment
# Install a vLLM wheel compatible with the host CUDA/PyTorch stack, for example:
python -m pip install "vllm==0.15.1"
python -m pip install -r requirements.txt
```

If the existing environment already has a working vLLM/PyTorch pair, do not
blindly replace it; install only the packages in `requirements.txt` and verify
the vLLM import first.

## Input layout

Put videos under `data/videos/<CASE_ID>/` and list the case IDs in
`configs/cases.txt`:

```text
data/videos/<CASE_ID>/*.mp4
data/videos/<CASE_ID>/*.mov
configs/cases.txt
```

Frames are written to `data/frames/<CASE_ID>/`; intermediate classifier files
go to `.work/<CASE_ID>/`; final files go to
`results/<model-tag>/<CASE_ID>_phase_query.csv`.

## Run the streaming video pipeline

```bash
bash scripts/run_video_pipeline.sh \
  --fps 1 \
  --extract-workers 4 \
  --queue-size 2 \
  --batch-size 16
```

By default extraction uses CPU ffmpeg so it does not compete with the VLM GPU.
If the host has enough GPU memory and CUDA video decode is desired:

```bash
bash scripts/run_video_pipeline.sh --hwaccel cuda
```

Useful checks before starting a long run:

```bash
python scripts/run_video_pipeline_parallel.py --dry-run
python scripts/run_video_pipeline_parallel.py \
  --model /path/to/phase-finetuned/medgemma-1.5-4b/fold0 \
  --dry-run
```

`--overwrite auto` resumes completed frame extraction and skips final CSVs
that already exist.  Use `--overwrite force` only when a complete rerun is
intended.

## Image pipeline

The existing image pipeline now uses the same MedGemma inference entry point.
Place case-organized images under `data/images/<CASE_ID>/` and run:

```bash
bash scripts/run_image_pipeline.sh
```

## Output contract

The final CSV is generated by `utils/video_jsonl_to_phase_csv.py` or
`utils/image_jsonl_to_phase_csv.py`.  The four phase labels remain:

```text
Diagnosis
Local injection
Incision / Dissection
Hemostasis
```

The MedGemma prompt is constrained to one of these labels and inference is
deterministic (`temperature=0`, `max_new_tokens=32`, `max_model_len=1088`).
